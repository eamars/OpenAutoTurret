# 03 · 冻结的自动实验方案

所有以下数字为**本版方案值**，不是已取得的实测资格。现场批准包络只能更严格，不能被算法扩大。

## A. 阶段与预算

| 阶段 | 固定动作 | 结束/后续 |
|---|---|---|
| 软件预检 | 保存脏树；解决/复核停止路径失败；完整通用回归；验证 registry/事务/trace | 失败不进入物理试验 |
| 会话预检 | 固定源码/二进制；确认硬件/模式/校准/可用保护；展开并冻结数值 manifest | 缺项 BLOCKED；不让 agent 猜 |
| 基线 | 10 秒静止噪声；冻结在线估计器及积分/slew 策略；同一候选双方向低速基线 | 验证度量可分辨、数据覆盖与真实参考 |
| coarse | 每轴 16 个机器生成候选，固定 3°/s，正反一对；整批参数来自预先落盘序列 | 有合格候选直接 confirm；没有才 refine |
| refine | 最佳两个有效 coarse 候选，各 4 个局部点；最多 8 组，一次完成 | 仍无合格解：NO_FEASIBLE_CANDIDATE，不扩域 |
| confirm | 最多两个合格候选，依排名逐个；3 个已批准姿态、双方向、每格 3 次、3°/s | 第一名全部通过即结束；不通过才验证第二名 |
| 扩展范围 | 5/10°/s、位置响应、真实归零、热与双轴试验沿 ADR-002 单列 | 未完成标 NOT_RUN；不能把低速筛选宣布全工况合格 |

基线不计入 16 个 coarse。每轴最多 25 个独立参数点（1 基线+16+8），不含相同参数的确认重复。重复次数小，报告每次/最大值，不宣称物理 p95 资格。

fixed seed：`20260930`。两方向先后顺序按 candidate 序号交替 `+− / −+`，并固定返回/预备条件。温度、姿态和时间不一致时不得假装严格同工况；按冻结工况块记录，禁止把冷态/热态混在同一个 summary。

## B. 搜索算法已经决定

使用**确定性的分层采样（Latin-hypercube 式一维分层置换）+ 一轮有界局部细化**。只用 Python 标准库；不为调参引入数据库、优化服务器或额外模型。

Yaw coarse 6 维：Kp、Ki、正向运行幅度、负向运行幅度、正向起动幅度、负向起动幅度。固定控制模式、估计器、slew、积分交接和上层参考；不要重新扫 20/30/40 ms 窗口。

本包给出的**报告域离线示例**是 Kp [1,8]（对数），Ki [0,0.6]（线性），各方向补偿幅度 [0,0.2] A。它来自 U1 已探索的数量级，但**不是经验证的安全域或实机授权**；Ki=2 的不合格试次不用于扩大默认域。起动幅度通过 `run + z*(upper-run)` 生成，z∈[0,1]，保证起动幅度不低于运行幅度。符号由已验证方向映射决定，不在正幅度里混入轴符号。

实机启动时必须将上述域与现有明确批准的 test range 取交集，再冻结实际数值。若没有明确批准域，给出 `BLOCKED_SEARCH_DOMAIN`；不能把 supported_range 或协议满量程自动当试验许可。报告域示例不得一键直接接到电机。

Pitch 只搜两个速度增益：Kp 的候选域为已读回 anchor 的 [0.5,2] 倍，Ki 为 [0,2] 倍，与该参数支持范围及批准 test range 取交集。anchor 必须来自实际模式下的有效读回；Ki anchor=0 或未知时输出 `BLOCKED_SEARCH_ANCHOR`，不要由 agent 发明正值。原有稳定 profile 提供已批准非零参考时可由同一公式使用，来源写入 lock。

每个维度划分 16 个等概率区间，以固定种子置换各维区间顺序并取中点，生成 16 组；Kp 在 log 坐标分层。浮点编码量化导致重复时去重并记录，不为凑满数量无限补点。

局部 refine 在归一化参数空间中，围绕两个中心每维 ±0.125（全域宽度的 25%），截在 [0,1]；各中心 4 个分层点，seed 依次为 20260931、20260932。不改变 mode、阈值、范围或分数定义。refine 的中心也由机器排名，不由文字报告选择。

## C. 候选比较与停止

所有方向/工况聚合采用最差值，不以正向优秀抵消反向失败。

有效但不合格的 coarse 候选，仅用于决定一次 refine 中心；以最大归一化质量违约程度排序。未完成/数据无效候选不得进入中心选择。硬保护触发中止 campaign，不允许搜索器把它只当一个低分样本后继续。

可晋级候选必须全部质量门槛通过，再按以下顺序最小化：

1. 所有有效方向中最大的归一化 jitter/跟随/漂移指标；
2. 同一指标的平均值；
3. candidate_id（稳定 tie-break）。

电流消耗不是排序项。任何一次饱和只记录；如果饱和但性能通过，不因使用大电流淘汰。性能不足且受限时报告 LIMITED_BY_ENVELOPE 诊断，不自动增大电流帽。

## D. 工况与轨迹

筛选先在已批准测试姿态完成。确认姿态由已校准的可用 pitch 区间取中点及中点±区间宽度的 1/4；这些点必须同时满足既有测试许可，不满足则 BLOCKED_GEOMETRY，不自行跨越已批准范围。

3°/s 是最终内环参考恒速段，不是 waypoint vref。稳态段至少 2 秒；此前参考到达与之后至少 2 秒停止保持有明确 phase。脚本检查最终 be_cmd 是否达到指定平台，否则该 case 为 INVALID_REFERENCE。

轨迹始终经过原限速/加速度/jerk 与停车路径。预先核对整个轨迹及可验证停止距离在批准运动区间内。报告中的 12°位移、1°非测试轴漂移限制仍按现有批准范围处理，不能因影响试验就删除。若规定刺激装不进区间，输出不支持该工况，不偷偷缩短窗口获得 PASS。

另一轴由既有控制器支撑；返回预备位与休息按固定 reference/稳定条件执行。不能用“停止”作为零扭矩的别名。

## E. runner 与性能效率

单个本地 runner 在 Pi 使用原 UDS 请求 controld，租约维持沿用当前已实现机制；它不直接访问 CAN。一次监督会话启动，自动完成参数事务、轨迹、归档、评分和下一步；无需每组 SSH、复制、调用 LLM。

控制实时性留给 C++。Python 采集/评分不得阻塞 200 Hz 控制线程；评分在 trial 日志关闭后执行。用户停止、监督链失联或保护触发时通过原受控结束路径退出；不擅自后台常驻。

## F. 完整状态机

`PRECHECK → FROZEN → APPLY → VERIFY → LOG_READY → RUN → FINISH → SCORE → NEXT/CONFIRM/DONE`

- APPLY/VERIFY 失败：ABORT_CAMPAIGN，后继试验不得启动。
- source/binary/hash 变化：ABORT_CAMPAIGN，建立新 campaign 后再试。
- FAIL_QUALITY：结束该组；不修改规则；按冻结次序继续。
- INVALID_DATA：条件可恢复时相同参数/工况恰好重试一次；再次无效则中止。
- HARD_ABORT：保护链处理并停止 campaign，不自动重复运动。
- NO_FEASIBLE_CANDIDATE：保存证据和明确不足；不 hand-tune，不扩域，不无限加预算。
