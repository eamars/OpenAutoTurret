# ADR-002.1 · Codex 必须执行的合同

你在实施**非武器化相机／传感器云台的实验基础设施**。不是重新设计闭环，不是进行人工 PID 调参。本次交付包不构成启动实机运动的授权。

## 0. 不得自行变更的决定

- 保留 ADR-002 的 yaw 电流模式与 pitch 原生速度模式；本版不切 MIT，不加新控制环，不调电调内部电流 PI。
- 不关闭急停、过流/过温、反馈失效、物理边界及命令失联保护。不将所有 limiter/guard 批量禁用。
- 性能失败不等于设备故障；淘汰候选调用现有受控结束路径，不自动让健康承重轴掉电。
- 参数改变：**0 次源码修改、0 次重编译、0 次重新部署**。改变算法/插桩才允许在 campaign 结束后建立新构建和新 campaign。
- 禁止逐组 SSH jog，禁止看完文字后人工选择下一组，禁止子 agent 接替这种人工选择。
- 唯一候选来源是冻结脚本；唯一评分依据是冻结 metrics 版本。不得临时提高 jitter threshold、扩搜索域、增加重试、删坏点或缩短不合格窗口。
- host 做 x86_64 通用测试和 ARM64 交叉编译；Pi 只收二进制、运行站台和硬件专用试验。不要因旧说明含糊而回到 Pi 编译。
- 活动 campaign 期间不得集成 PR3/PR4、修改头文件、构建、发布或让子 agent 修改共享测试树。此时子 agent 只可只读分析已经关闭的日志。

## 1. 第一阶段：只读保存与修复基础设施

读取实际工作区 AGENTS 和 operating runbook；记录 HEAD、dirty diff、已部署二进制 SHA-256、配置、未跟踪文件清单和报告里的停止状态。不要 pull 覆盖脏树，不盲目 stash/reset，不把 PR4 ignored 草稿视为已集成代码。

把报告中的 `park_power_probe` 失败作为 **known-unresolved**。先在宿主机重现并修复/查明该停止路径回归；不能只跑 5 项通过的测试而漏掉第 6 项。若实际工作区已经修复，必须以完整的新测试记录消除该阻断，不复述旧报告当作现状。

本轮只允许两个实现切片：

**A：registry + 应用/读回事务 + 完整 trace + 必需的停止路径修复。**

**B：单个本地 runner + 冻结 planner/scorer + 自动结果归档 + payload 绑定。**

复用原 UDS、controld、trace 和 profile 存储；不新建调参微服务、UI、数据库或优化平台。

## 2. 实验前必须交付

输出 `parameter_inventory.json`、`campaign.lock.json`、`runtime_snapshot.json` 和测试结果。缺一个都不得开跑。

registry 要覆盖现有所有控制可调项，包括算法开关、积分处理、slew 和估计窗；每项标明 writable/read-only/restart-required/unsupported。不可调项必须有原因，不能默默漏掉。运行时可调不代表本轮全部作为搜索维度。

`campaign.lock.json` 必须包含源/二进制/registry/metrics/参数域/阈值/顺序/随机种子的哈希、批准的试验边界、payload 身份、几何标定、最大候选数、每组重复数和异常动作。软件阶段可冻结自动生成规则；测量前必须冻结展开后的实际数值与顺序。

缺失的物理事实输出 `BLOCKED_<reason>`；不让 LLM 猜测填入。允许脚本按本包公式从已验证的读回值生成参数域，但禁止 agent 另定取值。

## 3. 执行规则

获得现有操作规程要求的会话授权后，仅通过一次监督会话启动 Pi 上的本地 runner。runner 经原 UDS 请求 controld，自己维持现有租约；不直接发 CAN，不取消租约，不以 SSH 逐轮充当实验调度器。会话结束/用户停止后不得残留后台调参进程。

每组严格执行：

`准备 → 原子应用 → 实际读回 → 版本/值一致 → 数据归档已就绪 → RUN → 受控结束 → 完整日志 → SCORE → 脚本选择后续`

参数应用失败、读回不一致、源/二进制改变：中止整个 campaign。禁止“应用命令失败但下一条 jog 继续”。不要用文件夹名代表实际参数。

性能失败只结束该候选，按既定脚本继续；明确的设备危险交给保留的保护链处理并中止 campaign。数据不完整只允许 **一次相同参数、相同工况**重试；第二次失败即中止，不换一组参数掩盖采集问题。

## 4. 报告与晋升

每个结果附 candidate_id、请求值、实际值、参数哈希、trace 哈希、有效窗口、全部指标与原因码。区分 `PASS_SCOPE` / `FAIL_QUALITY` / `INVALID_DATA` / `HARD_ABORT` / `BLOCKED` / `NOT_RUN`。

不把小样本描述成 p95 资格；不把低 jitter 但不跟随的候选算通过；不把温度 raw byte 当 °C；不把 optional IMU 缺失说成得到 IMU 佐证。

本包离线工具不是固件已完成。只有参数实机热更新测试、应用失败阻断、实验冻结、正反与规定姿态复验均通过，才算基础设施完成。候选晋升沿现有授权和原子 profile 保存流程，不能自动写入生产配置或自动部署。
