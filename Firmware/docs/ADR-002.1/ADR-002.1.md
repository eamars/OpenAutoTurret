# ADR-002.1：用冻结实验契约替代 agent 临场调参

- 日期：2026-09-30。
- 状态：Proposed；待本地实现和验证。
- 范围：ADR-002 的非武器化相机／传感器云台。
- 本地源码身份：报告声称 release `bad742dddba6.x1RrVx`；完整 SHA 见来源。未独立取得该源码。
- 覆盖：ADR-002 的调试组织方式、参数应用、试验取证、agent 决策权限。
- 不覆盖：既定分轴控制模式、不可旁路保护、机械资格和已批准电流边界。

## 背景与责任

用户报告确认 11 对/22 次 fine jog 的参数由主 agent 临时选择，脚本只完成发送、采集、计算。还有应用失败仍开跑、工况混杂、边调试边改源码和日志不重叠等问题。[U1]

上一版 ADR-002 已要求宿主机构建、分阶段验证和实际读回，但其调试章节仍使用“调 Kp、再加入 Ki、必要时比较窗口”的开放式表达，并给出若干人工 A/B 例子；没有把候选生成、预算、阈值和后续分支写成可执行合同。[P1, P2] 因此本版不是只要求 agent 更认真，而是撤销其逐次实验决策权。

## D1 · 安全边界不能靠删除解决

**否决“测试时关闭所有安全阀门”。** 允许放开的只是隔离 commissioning 会话中的生产性能/资格入口，且必须有批准的有限实验边界。下列三个层次必须独立：

| 层次 | 本版行为 |
|---|---|
| 质量指标：响应慢、跟随不足、轻度 jitter、过冲超出质量目标 | 记录 FAIL_QUALITY；必要时提前结束这一候选；不自动上升为设备故障或全轴撤能 |
| 实验包络：批准的时间、位置、速度、电流、非测试轴漂移、租约 | 全程有效；既是观测条件，也是风险边界；不得由搜索器放宽 |
| 设备保护：急停、真实过温/过流、反馈丢失、失控、物理限位、母线异常 | 不可旁路；沿既有安全路径处理，停止 campaign |

某个现有 guard 的名称含“性能”不代表它没有保护作用。分类依据其动作和保护对象；尚未完成分类的项默认保留。jitter threshold 是性能验收线，不是允许失控的最高幅度。

这里的 END_TRIAL / WAIT_AT_REST 是 runner 状态，不是业务 HOLD 模式。参数交换与候选结束时保持既有负载支撑语义；“速度归零”“位置保持”“零电流”“禁能”不得互换。

## D2 · 所有真实可调项运行时可见，试验值热更新

采用现有 UDS 上的一个 typed registry 与事务式应用接口，不新增服务。每一项必须有单位、真实绑定字段、支持范围、适用模式、读回来源和安全应用条件。机器可调与可观测项完整清单见 docs/02。

“所有参数”不包括虚构的电调能力。电调不支持运行时写入/读回的字段明确声明不支持，不能写进 YAML 后假装已经应用。控制主周期、CAN 拓扑、固件结构和安全硬边界不是可被优化器任意热改的候选维度。

## D3 · 应用成功是启动试验的不可跨越前提

prepare 验证全量配置，apply 在既有控制所有者中执行，readback 获取实际值；只有实际规范化数值与期待值一致才发 RUN。TX accepted 不能替代电调寄存器读回。多寄存器写不是物理原子操作；只对外提供“全部验证后提交一个 revision”的事务语义，失败须恢复并验证，不能宣称写入过程在电调侧原子化。

请求、回执、实际参数、日志都绑定 revision/hash。参数版本变化的 trace 不可混入同一 trial。对此必须有自动故障注入测试，特别复现 U1 的 Kp=2 请求失败但 Kp=1 开跑问题。

## D4 · 自动化不是用 Python 包装人工思考

冻结 `baseline → coarse → 条件式 refine → confirm → report`。候选和后续分支由本包规则生成，不由 agent 讨论决定。

选择**有界的直接性能搜索**，不在本版再开发物理系统辨识平台、贝叶斯优化服务、强化学习或复杂摩擦模型。这是效率与范围的明确选择；所得结果只是在既定候选域和工况中的合格解，不声称全球最优、摩擦模型正确或所有载荷通用。

默认 coarse 16 组；如果已有合格候选，跳过 refine；否则仅对评分最好的两个有效候选各产生 4 个局部点，共最多 8 组。最多验证排名前两名；顺序、种子、预算、重试次数均冻结。规则详见 docs/03。

## D5 · jitter 不能单独充当目标函数

恒速段同时检查位置残差波动、固定离线速度估计的抖动、平均跟随、持续运动、停止漂移和数据完整性。静止或爬行的电机即使 jitter=0 也不合格。

不使用随 candidate 改变的在线滤波速度评价 jitter，否则优化器可能通过加大滤波而不是改善物理运动“获胜”。离线评价算法固定，保留 raw encoder。初始质量目标沿用 ADR-002 的低速精度等级，并新增明确位置 jitter 目标；详见 docs/04。

## D6 · agent 只实施合同，不决定每次实验

由本包决定流程和公式；固件决定真实生效值；脚本决定候选与结果分支；操作者批准物理试验范围和生产晋升。agent 不得擅自扩大任何一项权限。

所有可预先决定的规则在这里冻结。必须靠现场确定的身份、参数读回、噪声、几何和温度由测量填入；缺项时脚本给出准确阻断原因，不能用语言模型猜测替代。

## D7 · 不追求最低电流，也不自动提高电流帽

排名不包含“更小电流更好”的惩罚项。允许使用已批准的可用电流，但调参算法不能改写批准边界，也不能以“已热平衡”口头声明替代温度测量。报告中的 0.8 A/5 A 只作为需在本地核对的配置边界，不被本包重新认证为持续额定值。

## D8 · 冻结源码，分离软件验证与物理结论

软件阶段修复必需的停止回归、registry、trace、runner；活动 campaign 不改源码。代码变化使原 campaign 结束，生成新二进制/metrics hash 后重新开始，不能把不同构建结果直接混成同一矩阵。

实机验收、热资格和原有完整 ADR-002 验收仍分别报告。离线 mock 全绿仅证明编排逻辑，不证明控制器稳定。
