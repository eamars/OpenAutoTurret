# ADR-003 · 给 Codex 的执行指令

本任务是相机快速跟拍的架构落地。当前交付包是设计，不是让你在收到文件时自动部署或启动实机。设计审阅阶段只核对必要接口、记录差异；获得实施指令后按下列完整范围执行。

## 1. 不可自行改变的决定

1. ADR-003只负责选定拍摄对象的视线状态、预测、跟踪参考及其验证。ADR-002.2负责物理伺服、前馈、积分、摩擦与电流约束。不得新建第二个电机PID或将目标速度直接乘常数变为电流。
2. 复用现有C++ `TargetEstimator`：每轴角度／角速度二状态的CV Kalman；明确修改不规则采样下的过程噪声语义和自动噪声拟合。**本ADR不实现显式目标加速度状态或加速度前馈，也不将其写成“以后必须补”的欠账。** 加减速、急停、反转均是同一模型必须验证的工况。
3. 目标状态以固定基座坐标系的相机LOS表示，在观测实际时刻消除相机旋转影响。禁止直接用pixel/s当rad/s，禁止再次把电机角速度加到已转换的基座LOS速度。
4. 每帧只更新一次估计器；200 Hz周期查询预测副本，不把重复帧变成新观测，不等待相机。200 Hz不等于相机200 fps。
5. `ReferenceManager`只裁决来源和求解几何；`track_reference`扩展后的生成器独占最终`q_ref/v_ref/a_ref`。所有轨迹量来自同一状态与离散积分，不能由不同模块分别生成。
6. Level1采用本包规定的“目标速度FF＋参考误差FB”的二阶跟踪生成器，不额外串联另一层`v=K*actual_error`控制器。实际相机误差分解为目标到参考的误差和参考到实机的误差，后一部分仅由ADR-002.2伺服修正。
7. 唯一预测时域在Level1计算。删除／停用ADR-003路径上的旧固定`motor_response_ms=120`和重复位置提前量；不是把所有服务共用设置全局清零。纯延迟与伺服动态分开识别。
8. 静止／运动使用同一控制器。速度不可靠时目标FF平滑归零，位置反馈继续；失去观测只能有限coast，随后沿既有停止路径保持。不能为了等待新帧而给电机Fault或掉电。
9. 不重写选择、ReID、检测模型、双摄融合、UI、归零、安全监督或部署平台。所有强制测试见场景矩阵；不得为了假想边界无止境扩展框架。
10. 阶段1完全无硬件；阶段2测量值自动注入；阶段3a／3b都要实机通过。ADR-002.2有效模型／标定／控制参数和已有测试证据优先复用，不重新扫PID。
11. 全部算法参数热更新并读回。参数变化不得改源码、编译或部署。单位／坐标／参数应用失败不可静默成功。复用既有参数事务、trace和profile存储，不再建设一套“更通用”的平台。
12. 工作站x86_64测试及ARM64交叉编译；Pi只执行设备程序。物理实验期间不集成无关PR或修改共享树。不得逐组SSH、看文字后手选参数；脚本根据本包数学规则一次完成数据处理和离线求解。
13. 保留必要设备保护与实际约束；性能不合格不等于硬件故障。不得以“优化反馈速度”为由扩大电流、行程或删除电机保护。
14. 没有用户摄影精度／响应要求或真实测量时，保持模板未知值，不编造最终验收数字。缺真实数据不阻塞阶段1；只阻塞依赖该数据的实机性能结论。

## 2. 接手只读核对

记录实际HEAD、dirty diff和部署身份，不pull/reset/stash覆盖用户工作。阅读当前AGENTS、文档索引、ADR-002.2及其阶段覆盖指令；只沿`01_SOURCE_AUDIT.md`列出的控制链核对。文件已移动则搜索对应符号，不克隆第二个项目。

明确标记：本地实际存在的控制核心与仅写在ADR中的目标能力。当前公开分支文档不能证明本地已经完成002.2的3a／3b。依赖未完成时继续ADR-003离线工作，停止在具体的硬件依赖上，不重做002.2来扩大本任务。

## 3. 四个实施工作项，不是四个可选版本

**W1：纯数学与接口。** 提取／复用一个`tracking_core`构建目标；实现本文公式、时间／坐标契约、唯一轨迹输出、模拟器及14场景。使用真实C++核心离线运行，不用Python重写另一份控制器。完成后报告阶段1软件结果。

**W2：实测数据与自动参数计算。** 复用现有采集／trace，仅增加缺失的光学观测时间、分段时延和几何／噪声记录；必要的native消息变更一次版本化。拟合时钟、噪声和参考带宽；复用002.2参数，不手调、不重编译。

**W3：独立程序3a。** 复用002.2的独立验证宿主与唯一硬件所有者，链接相同`tracking_core`及`axis_control_core`。执行真实光学闭环、规定比较及矩阵，失败按固定分类处理。

**W4：生产3b。** 接入真实visiond→正常选择／模式→参考管理器→轨迹→002.2核心→backend路径，验证正常预览／记录负载。只删除本路径重复的预测、参考求导和整形职责，不做全库清理。最终保存完整结果与适用范围。

## 4. 效率与停止规则

优先顺序固定：**时间／数据语义 → 单一状态与参考出口 → 预测质量 → 真实响应**。不要先换算法或先提高控制频率。

调参与模型计算全部在离线数据／仿真上进行。初始数据不足时，每次失败事件最多一次程序选定的补采包；采集故障只重试同一包一次。仍失败输出具体数据、模型或能力缺口，不临时加候选、加功能、加阈值。

必须工程处理的异常限于：无效／过期／乱序输入，目标／相机代际切换，速度置信不足，实际限幅与目标丢失。硬件故障直接复用002.2处理。新异常只有在研究稿明确要求、现有调用契约要求或实际可复现时才进入本ADR；其余记录而不开发。

## 5. 完成报告

报告源／二进制／核心／参数身份；1、2资产及复用；14场景结果；目标FF与电机FF的分开对照；3a与3b实机证据；曝光时构图误差、运动模糊指标和各段时延；尚未完成项及实际运行／停止状态。

`DONE`仅在全量约定能力和双验证通过时成立。中间提交可报告进度，不可称“首版完成，终版以后”。不以mock全绿、图像看起来跟上了、控制200Hz、没有fault或单次成功替代完成标准。
