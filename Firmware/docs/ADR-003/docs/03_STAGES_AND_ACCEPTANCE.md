# 03 · 三阶段、复用与验收

## 1. 单一完整交付

| 阶段 | 输入 | 完整交付 | 不允许的替代 |
|---|---|---|---|
| 1 纯数学／仿真 | 研究稿、接口、参数化相机／时钟／目标／002.2模型 | 方程、数据契约、求解器、同一C++核心、合成场景、评价器 | 等待实机才开始；用文档或TODO代替实现 |
| 2 实际反馈与参数注入 | 1的程序、旧有效资产、真实光学／时序数据、002.2能力 | 标定／时间／噪声／参数快照、适用域、自动计算候选 | LLM手选gain、反复实机搜点、修改源码常量 |
| 3a 独立程序实机 | 同一候选、真实camera→观测、独立宿主和002.2core | 有完整因果链的物理取景与执行证据 | 仅模拟、只放一段视频、仅向虚拟电机输出 |
| 3b 生产软件实机 | 对应3a、同core／参数／标定、真实production | 正常参考和输出链、预览／记录负载下相同范围通过 | production旁挂台架循环、仅加载JSON、绕过模式／参考链 |

阶段1完全不连接Pi、不读硬件寄存器、不需要真实日志；用显式synthetic参数覆盖约定场景。阶段2填入实测值后自动运行阶段1已经完成的方法，不再由agent选择模型。实机能力／授权缺失只阻断相关实机步骤，不阻断数学开发。

本次交付包仅规定上述开发工作，没有实现它们或执行相关测试。

## 2. 阶段1的必要测试范围

三个层次必须可独立运行：

**Level1＋理想执行器**：隔离目标估计、时域和参考误差。

**Level2＋合成q/v/a**：直接复用002.2的相同输入测试与有效证据，证明电机控制不依赖视觉。

**Level1＋实际002.2模型的仿真**：包含真实定义的延迟、采样、摩擦与限制。没有物理参数时使用显式合成模型；不宣称该结果是实际设备性能。

只要求与研究稿直接相关的14场景，以及少量接口不变量：自身运动不重复计入、q/v/a同一积分、同帧只更新一次、身份切换不继承速度、观测时间不被arrival替换、拒绝参数时不启动。无需穷举无关总线／电机故障；沿用002.2既有保护测试。

## 3. 阶段2的采集包

按固定顺序，优先复用有效记录：

**C1 时间与静态标定检查。** 真实像素、sensor raw、曝光／模式、metadata／publish／receive、encoder／gyro历史；用静止图案和受控相机运动检查自身运动补偿、偏差和时钟。需要重标定时沿用现有工具，不另建标定平台。

**C2 动态目标记录。** 独立标注的慢／快匀速、加减速、停止与反向，覆盖实际摄影范围；相机固定与相机运动的数据均需能区分。无真值时可做数据记录，但不能以估计器输出给自己打分。

**C3 端到端时序与负载。** 复用同一目标／模式数据，在正常预览和记录负载下取各段时延与actual reference。CPU时间、相机更新率、控制tick与真实输出分开。

R/q_a/λ与预测域按数学文档统一计算，一次保存。只有数学检查可行才输出实机候选。数据需要补充时每事件最多一次定向补采包；不可因此回到gain试验。

## 4. 摄影要求与接受阈值

研究稿明确禁止虚构最终接受数字。[R0 §19] 本包采用`photography_spec.template.json`，从既有明确摄影需求填入；无现成要求时保留空值，允许完成离线算法和测量，但不宣告满足未知性能要求。

### 4.1 必须在验证前确定的要求

当前相机／模式／焦距／anchor、允许的构图像素误差、最大运动拖影、要求的首次可用画面时间、最小有效画面比例，以及需要覆盖的目标角速度／加速度与距离／姿态范围。

这些是使用要求，不是电机协议最大值，也不是一次实验输出。优化器没有修改它们的权限。摄影目标超出002.2可达范围时报告ENVELOPE_LIMITED，不默默降低required_speed后宣布通过。

### 4.2 阈值的生成

- 构图像素预算经当前标定Jacobian变为对应LOS／joint角度预算，不固定使用旧FOV。
- 预测不确定性、标注／光学时间误差和002.2执行误差必须能被预算覆盖；不足报MEASUREMENT_LIMITED或ENVELOPE_LIMITED。
- 可用帧定义在训练前冻结：目标身份正确、实际曝光anchor在约定区域、拖影不超过预算。丢目标时的帧不能简单从分母删除；有意遮挡场景单独统计可见段与遮挡后的重获。
- 最终阈值、范围、数据拆分和评价器在参数验证前锁定；不能用验证失败的数据重定“稳态开始”或放宽门限。

## 5. 指标定义

| 指标 | 定义与时间基准 |
|---|---|
| 曝光时构图RMS／峰值 | 在真实帧有效曝光时刻测独立标注anchor相对指定构图点的像素距离；另给LOS角度 |
| 预测误差 | 在相同时间用独立真值与预测LOS比较，不用posterior给自己打分 |
| 匀速滞后 | 在有足够持续匀速且无饱和段内计算沿运动方向角差／目标角速度；近零速度不用此指标 |
| 首次可用画面时间 | 目标确认／用户选择时刻→第一张满足摄影spec的真实曝光；同时报告进入FOV之前的阶段是否可观测 |
| 停稳／过冲 | 已知目标停止时刻后，构图误差进入并保持在预算内的时间与最大反向偏离 |
| 反转误差 | 反转整个窗口峰值误差和恢复时间，不只截取反转后稳定尾段 |
| 静止jitter | 原始曝光anchor残差与实际角运动的波动；固定频带，不随candidate改变滤波 |
| 运动拖影 | 同次曝光内anchor路径的跨度；高频真值不足时报告由相对图像速度积分得到的上界，不能伪装为直接测得的光学PSF |
| 有效画面比例 | 满足冻结定义的帧数／场景全部应评估曝光帧数；另列丢失／无效原因 |
| 参考／伺服误差 | q_target−q_ref和q_ref−q_measured；不与目标估计误差混成单一PID成绩 |
| 时延 | 光学→发布、发布→接收、接收→使用、参考→TX、TX→响应的p50/p95/p99及原始分布；端到端直接从配对事件计算 |
| 资源与限制 | 控制执行时间、观测年龄、overwrite/drop数、输出饱和时长、电流RMS/peak；电流不是优化排名惩罚项 |

局部运动模糊的简化上界为 `B_px ≤ ∫exposure ||d(pixel_target)/dt|| dt`；若只知道近轴水平残差角速度可用 `f_x |ω_relative| T_exposure` 作诊断近似。图像散焦、被摄对象自身形变与云台跟踪不是同一问题；本ADR不承诺跟踪算法能消除所有模糊，也不扩展成自动曝光／快门调度器。

小样本只报告全部值／最大值，不以三次重复宣称可靠p99。长时延统计来自足够连续事件记录；重复性和统计不确定性按完整run计算，不把200Hz相关样本当独立试验。

## 6. 14项强制场景

所有场景都需阶段1，且最终在3a及3b证明相应真实控制／光学行为。延迟、丢帧、速度无效可在真实camera流的受控测试入口注入，不需要为它们建立新硬件系统。注入仅改变观测到达／有效性，电机与真实取景仍实际运行；报告清楚哪部分为测试注入。

| ID | 场景 | 必须证明 |
|---|---|---|
| T01 | 静止对象捕获 | ω_FF=0时仍能从角误差收敛；无不必要串联等待 |
| T02 | 静止保持 | FF趋零，实际取景抖动与漂移符合预算；必要支撑持续 |
| T03 | 慢速匀速 | 无“几乎不动但jitter低”的假通过；速度置信收敛 |
| T04 | 快速匀速 | 移动滞后、构图、有效画面优于可比基线并满足spec |
| T05 | 加速 | 创新及时改变速度估计，生成器与物理模型保持一致 |
| T06 | 减速 | 不因旧速度长期提前，参考动态平滑 |
| T07 | 突然停止 | 新观测纠正旧模型，停止／过冲与首次可用画面可测 |
| T08 | 方向反转 | 两层FF职责不重复，跨零无抖动切换或错误旧方向追赶 |
| T09 | 近零＋视觉噪声 | 无独立静止控制器，权重连续且位置反馈保留 |
| T10 | 速度估计暂不可用 | Level1 FF降到0，观测位置仍可用于跟随；恢复无参考跳变 |
| T11 | 延迟观测 | 使用光学时间与pose history，预测一次；关闭预测仍可闭环 |
| T12 | 不规则到达／丢帧 | 实际Δt传播、不重复帧、有限coast，无等待视觉的电机tick |
| T13 | 电机／轨迹饱和 | 输出有界、记录不可达、无无限积累；解除后不执行旧waypoint队列 |
| T14 | 丢失和重获 | TTL／置信衰减／保持明确，同身份恢复，新身份不继承速度 |

slow/fast/acceleration以冻结摄影需求与002.2可达范围定义；研究稿的30°/s仅为示例，不自动变成设备必须执行的数值。两个轴与同时运动都须覆盖，但可将多个情节放入同一条可复现轨迹并分别标段，避免为每个格子开发一个程序。

另外用固定场景验证相机自身旋转而对象不动时，基座目标速度应在测量不确定性内接近0；这是核心正确性测试，不是可选edge case。

## 7. 两种FF的分开对照

**A：Level1。** 采用相同观测、identity、低层参数与限制：

- FB-only：运动前馈=0；不使用目标速度做位置外推，按校正坐标后的最新位置收敛。
- FF+FB：使用本ADR预测与目标速度。

必须同时关闭“速度项”和隐藏在提前位置里的目标运动贡献，不能仅把显式FF设0仍让预测位置携带前馈。除该开关外数据、参数和参考实现相同。

先离线以同一held-out run比较；实机以相同可复现目标轨迹做配对／交替顺序比较。记录不同运行时目标和温度差异，不将它们假装严格相同输入。

**B：Level2。** 使用相同q/v/a，比较motor-model FF+FB与已经验证可用的motor FB-only。优先复用ADR-002.2在相同硬件／参数／适用域上的证据，不重辨识电机或每个场景都重复这一对照；不适用则由002.2测试入口补充必要证据。

目标层对照用于移动滞后，电机层用于轨迹误差。不能以其中一个成功代替另一个。报告另保留旧production整体基线，以区分新方法的效果与同时发生的002.2电机改进。

## 8. 实机真值与验证宿主

3a应使用真实camera观测已知／独立标注的移动图案或对象，独立宿主执行同一跟踪core和同一002.2 core，真实电机移动。可复用标定图案、屏幕轨迹或既有运动工装；目标的实际显示／运动时间需有光学或时间标记验证，不以“屏幕渲染调用已返回”当真实曝光时间。

3b用相同验证范围走真实production输入／选择／模式／reference／limiter／core／backend。保留正常preview和记录等用户实际负载。3a不连接业务状态机，3b不得绕过它。两者共享核心而不是手抄参数到另一套数学。

重新加载参数、launch和stop行为复用既有协议与证据；不为了ADR-003再建一套motor owner或故障注入平台。实体停止／急停仍由002.2负责。

## 9. 复用和变化

| 变化 | 应复用 | 应更新／验证 |
|---|---|---|
| 硬件、camera mode、参数、标定不变 | 1的全部软件；2的数据与标定；适用的002.2资格 | 新production版本涉及跟踪路径时验证对应3b，不能无理由全部重采 |
| payload／摩擦变化 | 003目标模型、光学标定、噪声记录 | 由002.2自动更新物理模型；003重算受影响带宽和参考能力，再3a／3b |
| 相机分辨率／crop／焦距或anchor source变化 | 未受影响物理模型和003算法 | 内参／像素映射、光学时间、噪声和影像预算；更新候选再双验证 |
| 纯处理／IPC延迟改变 | 几何、目标模型结构、物理数据 | 时间分布／有效时域，必要时重算参数，验证受影响范围 |
| 回到旧工况 | 旧数据／参数作为候选 | 身份与残差适用性检查；不能仅凭profile名字恢复PASS |

参数更新用既有registry原子应用和读回；实例化失败不得继续运动。若只有数据snapshot改变但行为未改变，保存证据关系；改变控制行为的候选必须绑定其新3a／3b结果。

## 10. 完成、未完成与避免无限扩展

每项必需能力必须实现，全部约定范围3a及3b通过才DONE。没有真实数据时写NOT_RUN，缺测量能力写MEASUREMENT_LIMITED，需求超出能力写ENVELOPE_LIMITED。不能把测试工具通过包装成实机完成。

有有限budget不等于测试失败可缩小范围。预算耗尽后保存失败，指出数据、模型、接口或能力缺口；不得让agent不断扩展框架来回避一个清楚的失败。

交付报告最少包含：现状diff、阶段1测试、阶段2资产和参数计算、14场景结果、两种FF分开对照、3a与3b身份对应、摄影指标与时延、限制／失败、复用决定及当前实际状态。复用现有记录格式；不再要求新建证书服务。
