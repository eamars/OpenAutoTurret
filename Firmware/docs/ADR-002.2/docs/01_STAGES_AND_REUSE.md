# 01 · 三阶段与复用规则

阶段1/2以[架构师覆盖指令](07_STAGE1_OFFLINE_OVERRIDE.md)为准；物理未知不得阻断阶段1。

## 阶段的输入、输出和通过条件

| 阶段 | 必需输入 | 可复用产物 | 通过条件 |
|---|---|---|---|
| 1 纯数学软件 | 源码/接口/设备文档、完整待估参数契约、明确标记的合成数据；无物理前置条件 | ModelSpec、ObserverSpec、模型/测量/辨识算法、控制器求解器、registry、采集协议与模拟接口、冻结评价规则 | 参数恢复与自动注入、求解、全部异常/变化分支的离线验证通过；无待实测后补的数学占位 |
| 2 获取实际系统反馈 | 1的产物、既有资产、现场身份/授权；先验证模式、停止保护、单位、标定和包络 | 能力证书、原始数据、MeasurementCalibration、PlantFamily、PlantSnapshot、联合不确定性/适用域、完整绑定模型与控制器候选 | 实测有效；整段独立留出支持模型；现有程序自动辨识/注入/计算，无改源码或手选参数 |
| 3a 专用程序验证 | 同一候选、当前工况、冻结评价器 | bench_validation证书、完整控制/传感器trace、变化与停止结果 | 真实设备、独立程序、覆盖矩阵全部通过 |
| 3b production验证 | 3a证书、完全相同候选/core/measurement、生产运行版本 | production_validation证书、适用范围、正式profile指针 | 真实production executable与完整正常输出链及负载通过，随后原子晋升 |

任何阶段中间产物都可保存，但没有缩减的交付状态。阶段2有数据不代表3已完成；3a成功不使profile自动成为production默认值。

## 三种身份，不能混成一个hash

**H：hardware_signature** — 电机asset/UID、驱动firmware/模式接口、输出轴齿比与符号、传动/机架几何、CAN拓扑、传感器型号/安装。换同型号电机也需确认身份。pitch旧资料的“直驱”表示机构连接方式，不得因此忽略电机内部减速比；全部单位在输出轴上校验。[R4]

临时进入归零mode或退出归零不等于硬件身份改变；H记录受支持/验证的控制接口契约，实际mode作为运行状态记录。不得每次正常归零就清空阶段1、2资产。

**C：measurement/control_signature** — 编码器物理零/映射、IMU安装矩阵/杆臂、时钟关系、采样/过滤、控制核心/构建ABI、电流编码与观测定义。会话tare/时钟偏移作为其有效session更新，不等于重建全部硬件模型。

**O：operating_point** — payload标识、可知质量/重心、姿态、摩擦/预紧状态、环境/电机温度、供电条件。未知项保留null并说明能否由有效反馈覆盖；不得用0假装已知。

模型族描述H/C下多个O，原始记录不可变。参数更新生成新snapshot，不覆写旧数据。不允许无限外插到未验证payload/摩擦/姿态区间。

## 复用判定（程序输出，不由agent凭感觉）

| 事件 | 复用 | 更新/失效 |
|---|---|---|
| 同硬件/标定/工况，健康探测及残差符合旧置信域 | 1、2全部可复用 | 3b绑定当前production版本；已有证书身份全匹配时无需无理由重调 |
| payload变化但仍在已支持工况族内 | 方法、测量资产、旧原始数据、已知模型族 | 选择兼容snapshot或数学插值/更新；参数变化必过3a/3b |
| 未覆盖的新payload或摩擦变化 | 方法/采集器/旧数据、与新工况仍相关的参数先验 | 自动定向补测、更新snapshot/不确定性，不能直接复制PASS |
| 返回旧payload | 旧候选和数据直接作为候选 | 健康/残差检查不符则局部更新；不能单凭名字匹配 |
| 摩擦随角度/方向变化 | 结构、时间/单位标定、惯量证据按兼容性复用 | 更新相关h表和起动区间，必要时联动重估；不强行固定已经不成立的惯量 |
| 电机/减速/传感器安装/电流模式改变 | 不受影响的软件和原始历史 | 精确失效受影响能力、标定、参数/控制证书，重做对应阶段2核验；仅明确模型/方法设计变更才修改阶段1 |
| 只有production调度/软件改变 | 原始物理数据、符合新观测映射的模型 | 重估实际端到端时延；3b重测，共用core变化则3a也失效 |
| IMU重启/tare或yaw会话零改变 | 原始资产保留 | 重建会话映射并验算；不得把会话0°当机械位置表0° |

**关键解释：复用的是能力、已测证据与适用的参数。复用不等于宣称未测到的物理变化不存在。** 允许在阶段3调用阶段2的同一求解引擎完成更新，不是重新“开发阶段2”。

## 持久文件与生命周期

采用已有profile原子写入机制和本地目录，不新建数据库。

```
calibration/<hardware_signature>/
  model_spec.json
  measurement/<calibration_id>.json
  data/index.jsonl                     # 原始run hash与时间、工况、身份
  plants/<plant_hash>.json             # 不可变；包括训练/验证数据划分
  candidates/<profile_hash>.json       # 候选，不等于已批准
  evidence/<profile_hash>/<3a|3b>/...
  active.json                         # 只有双验收后的正式指针
```

未提交/ignored运行数据保留在run目录，源码库只保存方法、schema和模板。活动指针可回退，但必须满足当前O的适用性；旧profile并非在新负载下天然安全。

阶段2数据按**整段run**分训练/留出，不能相邻采样点随机分割制造假泛化。若留出数据用于修正模型，其身份转为训练；必须取得新的独立验证数据。
