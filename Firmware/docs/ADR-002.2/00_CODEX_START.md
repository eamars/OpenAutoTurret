## 必须一次性交付的结果

交付可重复使用的自动系统辨识与控制器计算程序，完成：

**阶段1 建模；阶段2 获取实际系统反馈；阶段3a 独立程序实机验证；阶段3b production software 实机验证。**

只有全量需求矩阵完成且3a/3b均有对应实机证据，ADR才可标为 DONE。不得以“基础已完成、生产后续补”“先支持yaw”“先mock”“先手调成功再自动化”结束本任务。执行中可以报告真实进度/BLOCKED，不得把未取得的物理事实编出来以满足DONE。

## 不可由agent变更的决策

1. 不做 PID 实机网格/随机/16+8候选搜索；也不让LLM根据文字指标选下一组。基于实际反馈辨识模型，在电脑中计算与验证控制器，再做实机验证。数值求解允许迭代；每个优化点不得对应一次实机试参。
2. 阶段1、2的产物按身份和适用域复用。换payload/摩擦变化只更新参数资产及验证，禁止无理由从头重建、全量扫描或重新编译。
3. 独立 `commissiond` 负责辨识与3a；生产 `controld` 负责3b。它们互斥持有电机输出；Python分析程序不得直接发CAN。没有“两个发送者加一把局部mutex”的方案。
4. 两个可执行程序链接相同 `axis_control_core` 和低层编解码/单位转换。共享的不止Kp/Ki，还包括观察器、积分、前馈、抗饱和、输出仲裁、初始化和参数切换规则。不得Python台架调好后手译成另一份C++控制器。
5. 正常运动目标固定为yaw已验证电流接口、pitch经过本合同验证的电流接口；不调电调内部电流PI，不切MIT，不把host SI增益写进CyberGear原生速度增益。现有专门归零/停车路径保留并纳入模式转换验收，不能并行产生另一份输出。
6. 所有真实可调数值进入运行时registry，改变数值不得改源码、编译或部署。只读/不支持字段必须明确，禁止no-op成功。参数应用与读回一致才允许运行。
7. 3b必须运行真实production executable、正常reference/limiter/controller/backend/停止链；不能只回放、mock或在production中旁挂台架控制循环。完整生产负载和正常服务路径也须验证。
8. 冻结方法、评价规则、软件版本和试验边界，不冻结未知物理参数。模型更新由数学判据触发；每个新候选版本走3a/3b，不能把3a失败或旧3a证书与新参数拼接。
9. 不关闭急停、真实电气/热保护、反馈失效或机械边界；质量不合格与危险分开。正常可控摩擦/短时饱和不自动HOLD或全轴掉电。不能等待损坏发生才处理。
10. 电流不是最小化目标，允许使用工况已批准的额度；不得把协议满量程、旧资格或未知温度当成持续电流许可。
11. 工作站做x86_64通用测试与ARM64交叉编译；Pi只部署二进制并运行设备测试。活动物理试验期间不编译、不集成其他PR、不让子agent修改共享树。
12. 不新增数据库/云优化服务/仪表盘/MPC/RL。完整所需能力见requirements.json，不能用“不过度开发”删掉3b、payload变化、传感器校准或失败处理。

读取当前工作区AGENTS及运行规程；阶段1本地保存 `git status --short`、HEAD、dirty diff和本地构建身份。部署二进制hash、现场配置、实际电调模式、参数读回及保留校准的现场核对归阶段2，不是阶段1前置条件。不得pull/reset/stash覆盖用户工作。用户报告中的bad742d、PR3失败和停止状态均为历史报告，不当成现行源码或现场事实。

本包公开阅读基线是ADR-001分支的少量文件，不是本地bad742d源码审计。若函数已移动，用本地符号搜索只读必要调用链；不克隆第二份整库。

## 实施依赖，不是可删减的版本

依次完成同一交付中的：阶段1完整纯数学软件、参数契约与离线测试 → 阶段2底层能力/停止核验、实测标定、反馈辨识及自动参数注入 → 阶段3a → 阶段3b → 变化矩阵与全量报告。阶段3所需的变化检测、资产更新、生产加载与晋升必须在运行硬件验证前已实现并通过软件测试。数学软件完成、实机能力和设备资格分别记录。

不要每完成一个普通代码切片就要求用户重新确认是否继续；实际部署/运动仍服从既有授权。缺硬件能力/保护/授权时停在明确阻断点，不偷偷改设计或虚报完成。

## 决策与失败必须由程序产生

只允许文档列出的失败分类：DATA_INVALID、MEASUREMENT_LIMITED、INSUFFICIENT_EXCITATION、OPERATING_POINT_CHANGED、MODEL_INADEQUATE、ENVELOPE_LIMITED、INTEGRATION_MISMATCH、HARD_ABORT。按固定表处理，禁止一律“把Kp加倍”。有限补测预算、重试和解释规则见04/06；预算耗尽不是允许手调的理由。

原阶段1报告保留其历史 `NOT_RUN`，不能改写成已经做过物理验证。当前阶段2开始不等于采集通过，更不等于3a/3b完成。

列出实际source/二进制/core/参数/模型/测量校准hash；阶段1、2资产路径及复用判定；每个工况下yaw/pitch的3a/3b结果；payload±、摩擦±、恢复旧工况及未声明变化的证据；所有必需测试/失败/NOT_RUN；当前实际运行或停止状态；能否可靠回退到适用于当前工况的配置。

只有contracts/requirements.json全部满足，且正式验收器接受，才写DONE。离线单测通过不等于实机；“无fault”不等于平滑；源码中的配置值不等于已生效参数。
