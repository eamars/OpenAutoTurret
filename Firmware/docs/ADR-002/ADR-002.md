# ADR-002：分轴闭环与摩擦主导负载的平滑运动

- 日期：2026-09-29
- 状态：**Proposed / implementation-ready**，待实际工作区核对、分阶段实施及物理整定。
- 范围：非武器化相机/传感器云台的 GM6020 yaw 与 CyberGear pitch。
- 基线：`ADR-001` 分支选择性阅读；`base_commit=null`。本包不是从旧电压控制基线重新迁移。
- 证据：源码事实 [Sxx]、仓库现场记录 [Rxx]、厂商资料 [Vxx]、设计判断分别标明；索引见 [来源](sources/SOURCES.md)。

## 背景

操作者报告两轴使用交叉滚子轴承，起动阻力明显大于运行阻力；yaw 起动和响应慢，pitch/归零运动起伏。轴承型号、预紧、力矩曲线、实际载荷惯量和热态性能未提供，不能将所有现象都归因于摩擦或 PID。

当前 yaw 已经是 `0x1FE` 电流控制；主机速度 PI 的初始 Kp=1.0、Ki=0.6、输出上限 0.8 A。它不是只给固定电流，也不是缺少积分。更直接的问题是慢速误差产生的电流增长很慢、缺少摩擦前馈，以及无进展 guard 会与控制线程交替写电流/零电流。[S02,S04,S05,S06]

pitch 虽在硬件配置中声明 position，正常服务启用了 speed control：主机做位置 P 与速度前馈，电调做速度环；归零接近用 speed，退让用 position。不能因 YAML 的一个字段给 pitch 再叠一层主机速度 PI。[S02,S03,S07,S08,S10]

## 决策 1：两轴使用不同的最小闭环

```text
共同上层：位置/速度目标 → 现有轨迹约束 → 位置 P + 速度前馈 → 最终速度参考

Yaw：  最终速度参考 → 主机速度 PI + 有界静/动摩擦补偿
                       → 最终电流仲裁/抗饱和 → 0x1FE
                       → GM6020 内置电流环 → 机构
                       ← 带 RX 时间戳的编码器速度估计

Pitch：最终速度参考 → SpdRef / RunMode=2
                       → CyberGear 内置速度环 → 内置电流环 → 机构
                       ← 编码器用于外环；Iqf/状态用于诊断
```

主机维持 200 Hz；不因 yaw 反馈 1 kHz 就默认把 Linux 控制频率提到 1 kHz。pitch 静态/恒速时目前约 50 Hz 请求反馈，不是其内部速度/电流环只有 50 Hz；变化的命令可带来更多反馈。内置电流/速度环频率未从本次源码和资料确定，禁止填入猜测值。[S03,S07,V01]

## 决策 2：先修控制权冲突，再调增益

正常输出只由控制周期确定。guard 发布约束和健康状态，不以“无进展”为理由独立周期性覆盖零电流。真正的 watchdog/不可控危险仍可紧急接管，但必须阻止普通线程随后重新输出，直至明确恢复。

把性能问题、运动能力不足与危险分开。普通静摩擦、短暂饱和、单次历史 CAN 错误、一次仍可恢复的调度迟到，不自动跳 operational HOLD 或让两轴掉电。失去反馈、指令链失控、真实驱动故障、越界风险和不可维持的温度/母线异常，不能等到“已经不可挽回”才采取动作。优先有反馈的受控制动和支撑；Fault 状态与 torque-off 是两个决定。[S05,S06,S11]

## 决策 3：yaw 用已识别的起动力矩，不等小误差慢慢积分

在合法的电流/运动/热边界内加入一个小型摩擦补偿器：静止 → 起动补偿 → 已运动；反向先制动，再按新方向执行有限起动补偿。补偿依赖新鲜编码器确认和有效移动意图，不能在正常定点保持时不断触发。

起动电流升到当前载荷、方向、工况实测需要的值；确认运动后平滑减为运行摩擦补偿。PI 继续修正变化负载，积分基于**最终实际限幅/限斜率后的输出**抗饱和，防止破静摩擦后残余积分造成窜动。第一版不做复杂摩擦模型、在线辨识或无休止脉冲重试。[设计]

## 决策 4：pitch 先保留原生速度环；扭矩模式是有条件替代

先验证 SpdRef、编码器速度、Iqf、运行模式、限流和接触状态的时间关系，分离机械阻力、速度环振荡、主机参考台阶、模式切换和假接触。分别整定服务与归零参数，不改电调内部电流 PI。

若修正机械/时序、整定原生速度环后仍有可复现的限制，再做独立的 RunMode=3 电流模式 A/B：该模式能提供类似 yaw 的主机力矩权，但当前混合后端并未完整支持，`LimitCur` 在资料中只保证用于速度/位置模式；必须重新实现并证明 5 A 命令约束、停机及驱动异常保护，不能将 MIT 的扭矩范围直接当作 5 A 限流。[S07,S09]

## 决策 5：允许用满已合格电流，不把节能当目标

允许控制器用满该工况已经验证的持续/起动电流上限；目标是稳定起动、平顺、跟踪和制动，而不是寻找最低可动电流。

GM6020 的协议满量程 ±3 A、手册额定 1.62 A、连续堵转 0.90 A 是不同事实。手册还给出了工况/散热条件，不能把源码里的 `kMaxContinuousA=1.62` 视为所有低速和静止工况的热资格，更不能把 3 A 直接设为持续输出。本包不以手册中不同电流标签自动证明其与控制 Iq 的全部测量口径一致。[S12,V01]

第一批修复保留 0.8 A 已配置边界和 pitch 5 A 机构硬边界；完成资格测试后再批准上调 yaw 电流。0.8 A 不是长期优化目标或永久上限。允许峰值与持续上限独立，但不需要为此搭建完整热模型：先用可验证的温度、允许持续时间、占空/RMS、电源与机械能力记录。[设计]

## 决策 6：载荷档案绑定实际硬件与模式

现有 conservative 文件来自旧双 CyberGear 机构，`auto_verify:false` 只禁自动检查，并不禁启动加载；当前加载接口默认信任启动档案。旧字段 `gain_kp/ki/kd` 不能用于表达 GM6020 的电流输出 PI，也不能把其中 kd 当 CyberGear `spd_ki`。[S13,S14,S15,S08]

扩展现有 payload 存储，而非新增独立配置数据库。档案须绑定电机型号/ID、实际控制模式、机构/载荷版本及资格范围；保存几何校准与动力学校准的关联但不混为同一件事。payload 变化时重新测两轴的方向性起动、运行、速度/位置响应、重力负载和热态表现；不无故清除仍有效的机械零点。[设计]

## 不做的事

不重新开发电压→电流迁移；不修改 PWM 位置/速度 PID 来改善 CAN 控制；不同时提高两轴所有增益；不默认切 pitch MIT；不通过放宽所有保护“验证”顺滑；不把电流零、零速度、位置保持、禁能、物理掉电混写；不将一次探针成功或本包离线测试写成生产合格。

## 实施顺序与完成标准

PR1：证据/输出仲裁/错误恢复；PR2：yaw 摩擦补偿与速度估计/整定；PR3：pitch 速度环与归零；PR4：载荷重校准与合格档案。仅若 PR3 证明必要才实施 pitch 电流模式试验。

通过标准是两轴在定义的载荷与热工况内通过起停、低速匀速、反向、跟踪、受控停车与失效试验，而不是“没有报警”或“最终能动”。具体流程、建议目标与回滚见附属文档。
