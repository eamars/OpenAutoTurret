# ADR-004：固定倾斜安装下的重力平扫与水平 reticle

- 日期：2026-10-02。
- 状态：开发决策；本包未实施或操作实机。
- 依赖：用户确认已完成的 ADR-002.2、ADR-003；其有效资产优先复用。
- 位置：`Firmware/docs/ADR-004/`。
- 范围：两轴相机取景。固定但可非水平/倒置的基座；重力平面扫描与水平指示，不含连续移动基座稳定或第三轴/画面去旋转。

## 背景

选择性公开源码中，漫游使用固定的机械 pitch，`ControlLoop::roam_config()` 明确将 `level_scan_available` 设为 false；HUD 已有左右共线倾斜线及 `reticleCantDeg`，尚未自动接入 IMU。[S01,S02,S03] 这些接口支持局部扩展，不需要新的控制架构。

BNO085 的 game rotation vector 使用加速度计和 gyro，roll/pitch 参考重力，yaw 没有绝对方向、可漂移。[V01] 重力平面无需磁北。当前采集器同时输出原始 game quaternion 和 host 相对 quaternion，后者不能恢复启动时的安装倾斜。[S04]

## 决策

**D01 定义平扫。** 默认相机视轴在当地重力水平面内，world/gravity elevation=0。显式非零 elevation 只表示等仰角扫，不称水平视轴。已有机械 pitch 设置保留旧语义，不偷偷重解释。

**D02 定义能力边界。** 双轴决定视轴，不提供第三个独立 roll 自由度。物理可达性由校准行程、连续逆解分支、动态能力共同决定，不保证任意倾角的完整一周。存在侧置状态而不仅是正/倒二选一。

**D03 重力源唯一。** 原有 IMU owner → 原有 ingest → 同一控制侧 GravityFrame。使用 untared game quaternion、已标定 R_PS 和同一采样时刻的关节角。新模块不读取第二次 I2C，不另写融合器，不依赖磁罗盘。

**D04 基座参考稳定。** 在准静止窗口计算/确认 canonical up_B；扫描腿内冻结该重力帧，持续诊断，避免把自身加减速当倾角变化。实际搬动使当前扫描失效，受控停止后更新；不静默用旧平面继续。

**D05 正倒置是几何标签。** nominal base +Z 与 up_B 的夹角决定 upright/inverted/sideways。标签带滞回但不改电机符号、坐标标定、机械 limits 或视频安装变换。

**D06 使用已有几何。** 构造水平面 LOS，复用实际 R_PC 与既有 `LosJointSolver`。求连续关节分支、整条可行区间，而非每 tick 随意选择最近的另一个分支。

**D07 单一路径时间律。** 在 ADR-003 已确立的唯一 reference owner 内新增一个 `LevelSweepPath` 路径类型。单一扫描相位 φ 的导数通过链式法则生成两轴 q/v/a。不在输出后再叠一层独立 pitch 补偿 PID/平滑器。

**D08 保留动态留距。** 编码器限位是权威，工作保留区、实际停止可达范围、执行误差及延迟共同限制平扫；新层只收紧，不放开旧保护。普通收窄、减速、停止/反向不触发全轴 fault。

**D09 原有模式所有权不变。** 重力扫描是 AUTO_ROAM/显式 scan 请求的参考坐标选项，不新增业务模式树。目标捕获退出 scan 后回既有 ADR-003 基座 LOS 跟踪，不把两个 reference 同时送电机。手动关节 jog 语义不变。

**D10 倾斜影响动力学。** 正常竖直 yaw 的“无重力项”不是任意安装下的物理规律。倾斜时 off-axis COM 可对 yaw 产生重力力矩。将 up_B/安装姿态加入运行工况，调用 ADR-002.2 的已有模型适用性/参数重估，禁止另造经验重力电流。[P1的适用域原则；本项为新工况扩展]

**D11 reticle 保持形状。** 中心框固定，左右一根线被中间缺口遮开。线方向来自相机内外参和水平面投影，正角屏幕顺时针。不旋转中心框、不移动构图中心、不添加纵向臂、不通过布尔倒置重复翻转图像。

**D12 显示诚实。** 默认接现有状态遥测，标明 `CONTROL_POSE` 时间基准，不声称与无帧 ID 的浏览器 MJPEG 精确曝光同步。数据过期/望向竖直时不显示假水平。无需为此重建视频传输。

**D13 参数和证据复用。** R_PS、R_PC、相机像素变换、测量时钟、关节零点及控制能力按身份复用；改变 base 倾斜通常只更新 gravity_epoch/工况，不清除机械零点或重写模型。

**D14 开发纪律。** 纯数学阶段无实机依赖、参数热更新、独立和 production 双实机通过、单一完整交付。只做四个工作项；不新增控制/配置/日志平台。

## 数据和控制流

```text
现有 BNO085 raw game_rv + gyro/accel       编码器历史 + 既有测量标定
                    \                         /
                  GravityFrame(up_B, epoch, validity)
                        │                    │
                        │                    └→ 相机姿态/投影 → 既有 telemetry → HUD
                        ▼
       原有模式/来源裁决 → 重力方位路径 + 连续 LOS 逆解
                        ▼
           唯一约束轨迹生成器：同一 φ → 两轴 q/v/a
                        ▼
        ADR-002.2 axis_control_core → 既有 backend / 电机
```

## 不采用的方案

不直接用 IMU Euler roll 调 pitch；不固定 pitch 做名义平扫；不把每次 tare 当重力校准；不为知道水平引入磁北；不单独截断 pitch；不将水平扫描应用为所有目标跟踪的全局投影；不自动旋转视频/快门；不增设 base IMU；不实现通用轨迹优化器或 MPC。

已有简单正弦近似仅可作为纯数学小角度对照，不是实际算法。独立关节限幅可作为最后安全后备，但一旦动作破坏水平，应记录平扫已结束而不是宣告仍合格。

## 与旧 ADR 的最小契约变化

增加 GravityFrame、LevelSweepPath 及水平显示字段；物理 profile 的 operating_point 增加安装 up_B。扫描参考可行性使用两轴整段路径；旧固定 pitch 的验证函数不得继续充当新平扫判据。其他跟踪/伺服/选择/故障/部署系统不动。

完成标准见需求矩阵和阶段文档。有限行程下正确拒绝不可达段是必要行为，但不能以全部拒绝代替倾斜与倒置下的正向功能实机通过。
