## 9. P9 board 2026-09-03 (c) — printable sheet + a board-construction defect that hid as a skip

P9 needs a board **in the room**; the repo could not make one. It now can, and
making one exposed a real defect:

- `BoardSpec.make_cv_board()` passed `marker_id_offset` **positionally**, but in
  the Python binding that slot is the **ids vector**. Small grids produced a
  board whose ids did not match it → `CharucoDetector.detectBoard()` returned
  `None` while `ArucoDetector` saw every marker; bigger grids crashed outright
  (`Size of ids must be equal to the number of markers: 18`). Fixed (5-arg
  construct, offset rebuilt explicitly, dictionary-capacity check).
- `aruco.CharucoBoard((a,b), ...)` takes **squares**, and puts a marker on every
  black square: `(3,3)` is 3×3 squares = 4 markers, not a 3×3-marker (7×7 square)
  board. Anything sizing a printed board from the field name `marker_cols` is
  ~2.3× wrong, silently. `vision/charuco_board.py` therefore sizes the sheet
  **by measurement** (render → detect → measure corner spacing → resample →
  re-detect) and refuses to emit anything it cannot verify.
- Two tests in `test_installation_calibration.py` skipped themselves with
  "charuco detection returned no corners **on this build**", blaming OpenCV. One
  of them (`test_run_calibration_frontal`) *is* P9's end-to-end path — it had
  never run on this machine. Both now run and pass; the skips are now hard
  failures, because a skip is exactly how this survived.

unconstrained k1 on clean data predicted **6.116°** of edge error from a synthetic
set that has none, and laundering that number into a report would be worse than
reporting nothing. Validated against a known pinhole: **fx 0.503 %, fy 0.392 %,
cx 0.35 px, cy 0.14 px**. The produced pair was read back by a probe compiled
against `control/src` (`found=1 fx=613.456 …`, `pose: valid=1 source=3`).
