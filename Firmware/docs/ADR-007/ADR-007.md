# ADR-007: The one-shot actuator — a hobby servo that controld fires on the operator's command

- **Date:** 2026-10-30 (NZDT).
- **Status:** **Proposed 2026-10-30; the owner answered its three questions the same day**
  (section 6). The station check and the quick calibration are done (section 2). Stage 1 starts on
  the owner's go.
- **Request (owner, 2026-10-30):** a PWM servo added to the station. "The servo will rest at
  position A. On activate, move to position B, dwell for X ms then move back to position A." A
  calibration script finds A and B. Then the actuator goes into the stack, with its calibration in
  the existing calibration menu. Operator first, perhaps automated later. The page is tested on a
  synthetic web only: the real video feed is off limits.
- **Owner decisions, 2026-10-30:** controld owns the servo (not webd, not its own daemon). Operator
  first. A quick script first, then the page.

## 1. Context: the station today (measured 2026-10-30)

1. **GPIO18 is taken on this station.** The Waveshare 2-CH CAN FD HAT loads `spi1-3cs` and
   `mcp251xfd,spi1-0`: GPIO18 is SPI1 CE0, the chip select of `can1` (`spi1.0`), which
   `config/mixed_hardware.yaml` names the **pitch** bus. `gpioinfo` shows it held by `spi1 CS0`.
   Muxing it to PWM would cut the pitch drive off its controller. The notes from the other Pi
   (GPIO18, `pwm pin=18 func=3`) do not apply here.
2. **The servo is on GPIO15, physical pin 10** (owner, chosen for the wiring next to the 5 V and
   ground on pins 4 and 6). `pinctrl funcs 15` gives `a0 = PWM0_CHAN3`: the RP1 PWM0 block, the
   same one GPIO18 reaches. Nothing else on the station uses GPIO15: the serial console is the
   debug UART (`ttyAMA10`).
3. **The overlay creates the chip but muxes the wrong function.** `sudo dtoverlay pwm pin=15
   func=4` (owner) creates `pwmchip1` at `1f00098000.pwm` (found by address; the index is not
   guaranteed) but leaves GPIO15 on `a4` (RXD0). `pinctrl set 15 a0` (no sudo) puts it on
   `PWM0_CHAN3`. Both are runtime only and are lost at reboot.
4. **The signal reaches the pin.** At 50 Hz and 1500 µs, 22 of 300 `pinctrl get` samples read high
   (7.3 %, expected 7.5 %). A ±100 µs wiggle moved the servo (owner saw it). `can1` stayed at zero
   errors throughout.
5. **The quick calibration exists.** `tools/actuator_calibrate.py` (commit 5832893) jogs the
   servo from a terminal on the station, marks REST and ACTIVE, takes the dwell, test-fires, and
   writes `run/state/actuator.json`. It ends as it found the channel. The owner's calibration,
   saved 2026-10-30 21:50:54, with the servo off its mechanism:

   | | pulse |
   |---|---|
   | REST (A) | 1650 µs |
   | ACTIVE (B) | 1450 µs |
   | dwell | 300 ms (the tool's default) |

6. **What the stack already has, which the actuator follows:**
   - Every hardware write lives in controld; webd only relays commands, and
     `web/webd/tests/test_only_controld_touches_the_bus.py` checks it.
   - `web/command_validation.hpp` is the gate every command passes.
   - The watch point and the target type are persistent operator settings in `run/state/`, each
     with a store that writes off the control thread (write a temp file, rename it over).
   - Threads have classes (`common/thread_class.hpp`): motor threads are real time; web, IMU and log
     threads are Background (nice +10).
   - MENU › CALIBRATION is controld's session panel (ADR-005, ADR-006), and it ends where it found
     the station.

## 2. What is done

| Step | Result |
|---|---|
| Station check | GPIO18 conflict found before anything moved; GPIO15 chosen; overlay loaded by the owner; mux fixed by hand |
| Signal and motion | pin toggles at the measured duty; the servo moved |
| Quick calibration | `tools/actuator_calibrate.py`; A/B/dwell saved by the owner |

## 3. Decisions (proposed)

**D1. controld owns the pin; a worker thread writes it.** A new `control/src/actuator/` module:
`PwmChannel` (sysfs: find the chip by its address, period before duty, enable) and `Actuator`, a
small state machine on its own Background thread. The 200 Hz loop never writes sysfs and never waits:
it hands requests to the worker the way it hands a save to `WatchPointStore`, and telemetry reads the
worker's state from atomics. The shot's timing (B, dwell, A) is the worker's.

**D2. The launcher prepares the pin; reboot persistence is one config line.** Before it starts
controld, the launcher sets the mux (`pinctrl set 15 a0`) and checks that `pinctrl get 15` names
`PWM0_CHAN3`. It is configured by `OTA_ACTUATOR_GPIO` (default 15; empty disables, like
`OTA_IMU_RESET_GPIO`). To survive a reboot the owner adds `dtoverlay=pwm,pin=15,func=4` to
`/boot/firmware/config.txt` (sudo). A missing overlay, or a mux that does not take, is a **degrade**,
not a fault: the stack runs, the actuator reports `unavailable` with the reason, and ACTUATE is
refused with that reason.

**D3. The calibration lives in `run/state/actuator.json`.** It uses schema 1, already written by the
tool: `gpio`, `period_us`, `rest_us`, `active_us`, `dwell_ms`, `saved`. One optional key is added,
`hold_at_rest` (Q1), which is `false` when it is absent; the tool keeps it when it saves. controld loads it once at
start. A pulse outside 500..2500 µs, a dwell outside 0..5000 ms, or a GPIO that is not the
launcher's is refused on load. The file is not half-loaded: either it is valid, or the actuator is
`unconfigured` and the reason is logged and published. Saves from the page go through the store's
own thread. This is a station fact, like the watch point, and not part of a calibration record: a
payload swap does not move the servo. If it later rides on the payload, it moves into the record
(D9 of ADR-005).

**D4. The servo's lifecycle.**

| When | The servo |
|---|---|
| controld starts, configured | PWM on at A: the servo goes to A once, from wherever it was (a crash may have left it at B); then as "running" |
| running, Homed or Shutdown | `hold_at_rest: false` (the default, Q1): limp at A, PWM off after a 0.5 s settle. `true`: powered at A |
| ACTUATE | PWM on at A, → B, dwell, → A, settle, then as "running"; one shot; another ACTUATE during a shot is refused ("shot in progress"), never queued |
| STOP MOTION during a shot | back to A at once (STOP stays ungated, §27) |
| controld exits (signal, launcher stop) | A, wait 0.5 s for the travel, PWM off: limp at A |
| controld crashes | the hardware PWM keeps its last pulse, which is **B** if it crashed mid-dwell. The launcher's exit path writes A, waits, and switches the channel off whenever controld leaves without doing so itself |
| reboot | PWM off from boot: limp wherever it was, until controld starts |

**D5. Gating: the operator, and nothing else, fires it (owner, 2026-10-30).** `actuate` is accepted
when the actuator is configured and available, no shot is in progress, the station is not faulted
(a fault is a hazard: no new actuation beside one), the process-exit stop is not under way, and no
actuator calibration is open. Homed or Shutdown: see Q2. Automatic firing, from tracking, is not
part of this ADR. If it comes, it gets its own stage, with an operator ARM, a target lock rule and
a refire interval.

**D6. Commands.**

- `actuate`: one shot.
- `actuator_calibration start|stop`: the session. It opens only while no shot is in progress, and
  closing it returns to A, with the saved values if the session saved, otherwise the old ones.
- `actuator_pulse <us>`: inside a session only, 500..2500 µs.
- `actuator_test <rest_us> <active_us> <dwell_ms>`: inside a session; one shot with unsaved values.
- `set_actuator <rest_us> <active_us> <dwell_ms>`: inside a session; saves and is in force at once.

Each has a reason on refusal (§52), like every other command.

**D7. Telemetry.** One object, `actuator`: `available`, `reason`, `state`
(`off|rest|active|returning|calibrating`), `pulse_us`, `rest_us`, `active_us`, `dwell_ms`, `shots`
(this session), `last_shot_age_ms`, `persistent` (the state directory exists).

**D8. The page.**

- An ACTUATE button of its own, below the D-pad, in the red tone (Q3). One press: the two-press rule
  is SHUTDOWN's alone. When refused it is greyed, with the reason.
- MENU › CALIBRATION › ACTUATOR, with the same controls as the tool: PULSE −/+ with steps of
  50/10/2 µs, MARK REST, MARK ACTIVE, DWELL −/+, TEST, SAVE, and ‹ to go back. It shows the live
  pulse and the saved values beside the marks.
- Leaving the panel by any route closes the session at A (ADR-006's lifecycle rule).
- Built and checked against webd with `fake_controld.py` and the tests' fake camera on the
  workstation only (owner, 2026-10-30: no real video feed).

**D9. The quick tool steps aside.** Once controld owns the servo, `tools/actuator_calibrate.py`
refuses to start while the channel is enabled ("controld owns the servo: use MENU › CALIBRATION ›
ACTUATOR, or stop the stack"). It stays as the bench tool for a stopped stack.

## 4. Failure modes

| Failure | What happens | Covered by |
|---|---|---|
| overlay not loaded (reboot without the config line) | no chip at `1f00098000`; actuator `unavailable: overlay not loaded`; everything else runs | D2 |
| mux not taken | `pinctrl get` check in the launcher; `unavailable: GPIO15 not on PWM0_CHAN3` | D2 |
| file missing or malformed | `unconfigured`, reason published; ACTUATE refused | D3 |
| sysfs write fails mid-shot | the worker retries A once, then reports `unavailable` with the error; never left silently at B | D1, D4 |
| controld crash mid-dwell | the launcher's exit path drives A and switches off | D4 |
| ACTUATE pressed twice | the second press is refused while the first shot runs | D4, D5 |
| servo stalls on its mechanism at A or B | not detectable without feedback; the calibration's job is to keep A and B off the end stops, and the card says so | D8, card |

## 5. Stages

1. **controld:** the module, the launcher's pin preparation and exit path, the commands and the
   telemetry. Unit tests for the state machine on a fake channel and for the gate. Deploy, then
   check on the station through the JSON API only: ACTUATE, the telemetry, a refusal, STOP during a
   shot, a launcher restart. A crash test (a targeted kill of controld during the dwell) runs only
   if the owner agrees.
2. **The page:** the ACTUATE button and the calibration panel, tested on the synthetic web.
3. **The card:** `operations/actuator.md` (calibrate, fire, recover), linked from the docs map,
   `doc_tree_check.py` clean.

## 6. The owner's answers (2026-10-30)

- **Q1. At rest, powered or limp?** **Configurable, limp by default** (owner: "Rest is supposed to be
  no load, but things may change"). `hold_at_rest` in the file, `false` when absent (D3, D4). A
  calibration session holds the servo powered at its pulse whatever the setting is.
- **Q2. ACTUATE in Shutdown?** **Yes, in any state except Fault**, the exit stop, and an open
  actuator calibration (D5).
- **Q3. Where does ACTUATE go?** **Its own button, below the D-pad, in the red tone** (D8).
