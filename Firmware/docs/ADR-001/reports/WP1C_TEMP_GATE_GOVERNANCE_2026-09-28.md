# WP1c 治理：yaw 那个裸字节从"闸"降为"观测"（2026-09-28）

范围：只动 yaw 的**温度裸字节**守卫。**没动**：其余九项守卫条件、5 A 上限、反馈时效 100 ms、
pitch 的 `motor_overtemp_c: 75.0`（那是 CyberGear 真摄氏度口径，另一种东西）。

## 1. 判决（改的是什么）

`Firmware/config/mixed_hardware.yaml`：`guard_temp_raw_ceiling: 75` → **`0`（拆闸）**。
键仍是必填（缺键仍拒启动、>255 仍拒），**语义变成"这台站的选择是：不用这个字节断电"**，
不是"忘了配"。同时把裸字节变成看得见的东西：1 Hz 遥测行新增 `temp_raw_pitch=` / `temp_raw_yaw=`
（`-1` ＝ 没收到过字节）。

## 2. 三条支撑证据（都可在现场/仓库复核）

1. **官方口径**（`docs/references/gm6020/GM6020_AI_Reference.md`，抄自 v1.4 PDF）：
   反馈帧字段里**没有 enable/disabled 位、没有故障码、没有 fault-clear**；
   指南说异常状态会切输出，但**不定义 CAN 层的故障上报**。
   ⇒ 主机侧那个字节**不是一个过温信号**，它是"一个没有单位的字节"。
2. **总线普查（2026-09-28 03:5x，被动听 `can0`，15 s，不动所有权）**：
   ```
   0x205  n=15000  first=0c5a0000ff7c1c00   ← 反馈，1 kHz（与指南一致）
   0x1FF  n=2966                            ← 我们自己的 200 Hz 命令
   ```
   **没有第二种状态帧**可被"提拔"成故障源。`0x205` 解码：角度 0x5a0c、转速 0、
   电流 0x7cff=−913（与我 logger 里的 −886…−933 对得上）、温度字节 0x1c=28、末字节 0x00。
3. **热平衡夜跑（同一夜，主人设计的实验）**：带电 HOLD 71 分钟，yaw 字节 **36 → 32**，
   断电后继续掉到 30；pitch 全程 25.9 °C；Pi CPU 50 → 44 °C。
   ⇒ **这个配置、这个电流档下没有自热可防**；昨天"3 小时带电积热"的解释被削弱（注意：昨夜起点 41／电流 2127，与今夜 ≈900 不可比）。

**再叠加主人 09-27 的裁决**："只有 motor 自己报的过温才配断电"——
GM6020 **没有** such 信号，所以按他这条裁决，**裸字节闸本来就不该有断电权**。
今天只是把代码改成和他说的话一致。

## 3. 那 yaw 的热保护剩什么（我不假装拆了闸还有同等保护）

| 层 | 还在不在 | 说明 |
|---|---|---|
| 驱动器自切输出（指南：125 °C） | **在** | **但是哑的**：没有 CAN 报警位，切了我们只能从"不再反馈/不动"里推断 |
| LED 100 °C 警告 | 在 | **现场不可见**（要人为看一眼），未做标定 |
| 行为守卫其余九项（CAN 健康/心跳/无进展/速度上限…） | **在** | 未改一项 |
| 主机裸字节 ≥N 跳闸 | **拆** | 换成观测：1 Hz 行 + 跳闸矩阵里的 `temp_raw=` |
| pitch 真 °C 过温（`motor_overtemp_c`） | **在** | 不受本片影响 |

⇒ 诚实说法：**拆掉的是一条本来就没有物理含义的闸**；换来的是"少一个假绿、少一次误跳"。
若将来要用它当真温度，得先做 **LED 锚定标**（主人陪一场热机），届时把标定写进这个键旁边，
而不是再猜一个数。
