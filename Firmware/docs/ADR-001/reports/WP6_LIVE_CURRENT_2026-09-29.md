# WP6 · 现场第一手：偏航在 `hold` 里带着 0.8 A 的保持电流

**日期 2026-09-29 上午｜发布 `8cbb2e7cb2ea.PVDtX3`｜站点 192.168.2.103｜第一次有人从 HTTP 读到 per-cycle 环。**

## 为什么这一页存在

`07_WORK_PACKAGES.md` 给 WP6 的话是「**每轴/方向/载荷数据支持**」。昨天以前这句话没有一条能落：
偏航的力矩电流在 `gm6020::decode` 里被解出来，然后被丢掉——`mixed_can_motor_backend.cpp`
把 `torque_nm` 直接写成 NaN，序列化器注释还写着「GM6020 状态帧里没有数值」。
**帧里有数值，就是那个电流**；我们解了它，然后扔掉它。`commit 8cbb2e7` 把它接出来，
列名 `cur` / `current_a_*`，**单位安**，不与 `effort`（N·m）混列——手册没给转矩常数，
把安除成 N·m 就是拿一个推断值冒充熟悉的名字。

## 看到的（两次采样，各 256 行 ≈1.29 s，间隔 8 s；`mode=AUTO_ROAM`）

| | 第一次 | 第二次（+8 s） |
|---|---|---|
| `phase` | 256/256 `hold` | 256/256 `hold` |
| yaw `cur` | 256/256 有值，**−1.057 … +0.165 A** | 256/256 有值，**mean −0.813**，−0.994 … +0.119 A |
| pitch `cur` | 全 `null`（CyberGear 报转矩不报电流，按规矩是 null 不是 0） | 同 |
| yaw `temp_raw` | 25 | **37** |

`/api/state` 同一刻：`current_a_yaw = −0.803467`、`current_a_pitch = null`、`effort_yaw = null`。

## 这三行数字各说各的事

1. **轴在 `hold`，却持续带着 −0.8 A。** 这不是"静止=没受力"的反证，是它的第一个量化形式：
   **站台的"待着不动"这件事本身就顶在 host 包络（0.8 A）上**，而且带内还有 −0.99 A 的瞬时越出
   （反馈可以报出超过指令满量程的值，accessor 不钳位，这是有意的）。
2. **`temp_raw` 一分钟内 25 → 37。** 这个字节**没有 °C 换算**（§WP1C：GM6020 没有已确立的 °C 换算，
   只作相对量）。能说的只有一句：**在 `hold` 里以 ~0.8 A 待着，它是在发热的**。
   不能说的也写清楚：这不能换算成摄氏度，因而**不能**据此判决"热跑没问题"或"该抬上限"——
   那正是主人 09-29 裁决「暂时不变」要等的那次热测。
3. **两个方向不对称**（−1.06 A vs +0.17 A 的范围）。两次窗口都在同一个位姿里，
   所以这只是**一个位姿上的一个方向偏置**，不是每轴每方向的辨识表——M1 那张表还是没做。

## 与既有结论的关系

- 09-29 凌晨那轮（`logs/drag/`、`Firmware/docs/.../OWNER_RULINGS_2026-09-29.md`）证明的是
  **破静摩擦需要 >0.8 A、匀速只要 0.4–0.5 A**。今天这条补上中间那块：**站住不动时它已经在要 0.8 A**——
  也就是说"起步不够力"和"停着就顶包络"是同一件事的两端，中间缺的是**为什么 `hold` 需要力**
  （线缆束张力？某个 binding 扇区？参考与实测的稳态偏差？），这一条**归 ADR-002**，
  而且从今天起它有数据可看了。
- **不作为**「上限该抬」的证据：没有热测；`temp_raw` 不是温度。
