|---|---|---|
| **M1** | 停止包络（方向/滑环相关） | 002 的 yaw 来回扫本来就产生大动作：在扫的两端各触发一次 OBS，取 `stop` 证据链（WP2 的形状），**同一批 trace 里就能算** |
| **M2** | 停止包络（持续段） | 同上，用 002 的 `--yaw-step-deg 15..45` 出/回程，无需额外跑机 |
| **WP2-N1** | 停止证据的一条 | 002 第一次停栈时顺手采 `synthetic_stop_evidence` 的真机版 |
| **C1** | 跨镜留出集（LOS 残差 p95 ≤ 0.5°） | 002 必然要人在两镜前移动：**同一趟**录 5 分钟，两路都带 `camera_id`，回来离线算残差 |
| **V0 / WP5 分数分布** | 检测分数分布 | 002 期间有人在镜头前，`--record-dataset` 顺手跑 10 分钟即可 |
| **WP7** | 关联 / 仲裁 / AprilTag 行为验证 | 002 的yaw 扫动 + 真实目标 = 关联的天然压力测试；002 结束前留 15 分钟专跑这条 |

**为什么这些今晚不做**：它们全都需要"yaw 能被稳定驱动"这个前提，而该前提正是 ADR-002 的产出。
在前提未成立时跑出来的数，明天还要重跑一遍——那不是验证，是重复劳动。

**新开的账**
1. **`control/src/telemetry/telemetry.hpp:314` 那句注释是错的**："There is no inertial sensor on this station"
   ——BNO085 在 I2C1:0x4a，且今天真的在出 215 Hz。`imu_present` 等三个 §20 字段**至今无人赋值**。
   ⇒ 要么从 `ImuTraceIngest::snapshot()` 抬上去，要么把注释改成实情；**不阻塞 UI，因为 webd 现在直接读 trace**。
2. **两条流的身份基数不同**（wide=by-path，detail=fwnode）。都是端口级、都 durable，但**该统一成 fwnode**
   （libcamera 对两颗都给 `Id`）。今天不改是因为 wide 那个 id 已被别处引用。
3. **detail 的采集几何写死在 `DETAIL_STREAM_MODEL_DEFAULTS`**（1280×720@30）⇒ 该进配置。
4. **双流还没接进推理调度**：`detail` 现在只出预览，不进 Hailo（3C）。共享推理调度归 `PerceptionPipeline`，
   不是往采集线程上焊。**这条是 B 路生产化的最后一块，也是 002 之后我的下一件。**
5. `hq_zoom_fov.json` 的 base FOV 仍 `not_measured`。
6. 基线缺陷仍开：`STOP FAILED` 关停顺序、yaw watchdog 打印 `feedback_age_ms=-1.000`/`temp_c=0.0` 当实测、
   归零 ~40 s、`/api/telemetry` 404。
